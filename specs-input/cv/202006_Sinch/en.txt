Title: Sinch Chat Messaging (SCM) for Salesforce Marketing Cloud (SFMC)

Joint Sinch–Salesforce project enabling SFMC to send WhatsApp business messages via Sinch Conversation API, which transcodes messages to each network's native format with multi-channel fallback. Sinch's responsibility was the provisioning and configuration UI; Salesforce handled the sending side. Users signed in to SFMC were handed over to the configuration application through a JWT-based OAuth flow. The requirement that shaped the design was that no communication with Salesforce could be lost and that billing had to be provably correct.

Working primarily as a backend developer on the provisioning UI system, I introduced Kafka to consume change events from internal services such as account status and wrote a custom Kafka transport for NestJS so that messages were not dropped, added Bull queuing with retries for reliable outgoing REST calls to SFMC, added a separate audit log that made every billable event checkable afterwards, and led the rewrite of the BFF from Express to NestJS. I also contributed to frontend work and made changes across most parts of the codebase.

The system comprised four TypeScript/NestJS microservices — a React frontend (Salesforce Lightning Design System) served by Nginx, a BFF (Apollo GraphQL with Redis sessions), a PostgreSQL database service, and a Salesforce callback handler — communicating internally via gRPC. E2E tests were implemented with Cypress and unit tests with Jest. Services were deployed to Kubernetes on AWS via Docker and GitLab CI/CD, monitored through Grafana and Graylog.

Development followed Sinch's one-week Kanban cycle with longer-term planning through OKRs, tasks in Jira and Confluence, and source managed in GitLab with GitFlow-style branching.
