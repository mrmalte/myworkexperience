Title: Fixa

Fixa is Ikea's internal store operations application — a suite of features bundled as one app for managing daily in-store tasks such as article restocking and showroom upkeep.

Working as a software developer I delivered two significant features. The first was a unified filter component system replacing around five separate filter implementations across the app. Filters are assembled from a partly programmatic configuration that fetches its options through hooks and callbacks, so one choice can change which choices are available next, and where the selection is stored is itself configurable: in the backend database, in local storage or in memory. The filters became consistent and easier to use, and adding filters to more views became largely a matter of configuration. The second was an in-store notification inbox pushing messages to the frontend via Server-Sent Events triggered by database changes — later extracted into a standalone Cloud Run service provisioned with Terraform. Deploying the notification service also required updating service-to-service communication to use the private VPC network instead of public addresses. The interface designs came from the UI designers as Figma files, which I worked from closely while implementing them. I also handled smaller features and bug fixes throughout.

The system is implemented in TypeScript with React/Styled Components/CSS Modules frontend apps using TanStack Query for data fetching. Each feature has its own Fastify/Knex backend, in effect a BFF calling Ikea's internal systems, with its own PostgreSQL database for application data. Sign-in goes through Entra ID and MSAL, with an Ikea-specific authorisation layer on top that ends in the JWT the backends validate. Initially each feature had its own frontend and backend repository with individual CI/CD pipelines; the backend repositories were later consolidated into a single Nx monorepo. All services are deployed to GCP with a common Terraform setup.

Development followed a weekly Kanban/Scrum mix with a focus on short, effective planning meetings. Copilot was integrated in GitHub and the IDE, agents could open pull requests and Copilot reviewed every pull request; the documentation, however, was the code.
