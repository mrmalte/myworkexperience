# CLI and Output Contract: `npm run linkedin:build`

## Command

```bash
npm run linkedin:build
```

Resolves to: `tsx tools/build-linkedin.ts`. No arguments, no flags, no network access.

## Inputs

| Input                          | Source                                       | Required |
| ------------------------------ | -------------------------------------------- | -------- |
| Compiled site content          | `public/content/site-content.json`           | Yes      |
| Authored LinkedIn copy (en)    | `specs-input/linkedin/en.txt`                | Yes      |
| Authored LinkedIn copy (sv)    | `specs-input/linkedin/sv.txt`                | Yes      |

## Outputs

### Success (exit code 0)

`linkedin/linkedin-en.md` and `linkedin/linkedin-sv.md`, overwriting any previous run. The directory
is created if absent and any `linkedin-*.md` from an earlier run that is no longer produced is
deleted first (FR-014).

**stdout**, in the style of the other build tools:

```
=== LinkedIn Build ===

Reading site content...
Reading specs-input/linkedin/...
Matching 34 assignments to 16 employments...
Building 23 LinkedIn positions...
Generating linkedin-en.md...
  ✓ linkedin-en.md
Generating linkedin-sv.md...
  ✓ linkedin-sv.md

⚠ Over LinkedIn's limits (trim before pasting):
  [en] Software Engineer @ Connected Table — 2104 / 2000 characters

✓ LinkedIn build complete!
  Files generated: 2
  Output directory: linkedin/
  Unmatched assignments: 0
```

Over-limit blocks and unmatched assignments are reported but do **not** fail the build — they are
editorial findings, not errors.

### Failure (exit code 1)

No output files are written or modified. One message, naming the path and the fix:

| Condition                                  | Message                                                                                            |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `site-content.json` missing                | `Missing public/content/site-content.json — run 'npm run content:build' first`                      |
| `specs-input/linkedin/{lang}.txt` missing  | `Missing specs-input/linkedin/en.txt`                                                                |
| First non-empty line is not `Headline:`    | `specs-input/linkedin/en.txt: first non-empty line must be 'Headline: ...' (got '...')`               |
| `Headline:` value empty                    | `specs-input/linkedin/en.txt: Headline value must be non-empty`                                      |

Error wording follows the existing convention in `tools/content/parseSource.ts`
(`<file>: <what was expected> (got '<what was found>')`).

**Rules that make the paste blocks safe**

- Every block a human copies is inside a fenced code block; nothing else in the file is meant to be
  pasted.
- Inside those blocks: plain text only. No markdown emphasis, no `#`, no `- ` bullets. List items
  use the literal `•` character (FR-012).
- Counts are rendered as `count / limit`, with ` ⚠ over by N` appended when exceeded (FR-010).
  Never truncated (FR-011).
- The header line under each position heading carries LinkedIn's own field names, so each value has
  an obvious destination in LinkedIn's form. `Title` is the entry's own per-language title; when
  `meta.txt`'s `Role` differs it follows as `(CV role: …)`, because for some entries Role is the
  better LinkedIn title (MultiQ: Role "Software Architect" vs title "Software Developer") and for
  others the title is (Teleca: title "Module Owner" vs Role "Software Developer"). Only `title` is
  authored per language, so a Swedish profile built from `Role` alone would read "Consultant".
- Blocks come in three kinds — `client`, `in-house` and `umbrella` — decided per employment as
  described in [data-model.md](../data-model.md#block). A client block whose group holds a single
  assignment carries that assignment's description in full; a group with several carries one bullet
  per assignment. In-house blocks carry the employment description followed by one bullet per
  assignment, labelled by the assignment title alone since the client is the employer.
- An umbrella block carries the line "Umbrella position for the employer — the client assignments
  below sit inside this period." under its header, so the reader knows it is deliberate overlap.
- The over-limit sample above is illustrative: with the CV as it stands, no block exceeds its limit
  (the largest, Connected Table, is ~1 700 of 2 000) and the run prints no warning section.
- "Unmatched assignments" is always present, reading `None.` when empty — its absence would be
  indistinguishable from a tool that silently dropped work (FR-005).
